## 5.1.0

* renamed test_runner_settings.r_environ_path to test_runner_settings.r_environ_session_path
* requires **PHP 8.4 or newer**; the Docker image now runs **PHP 8.5** (official 8.5.12 release, built from source) instead of the PHP 7.4 security backport
  * Docker: PHP configuration moved from `/etc/php/7.4/` to `/etc/php/8.5/`, and the FPM binary from `/usr/sbin/php-fpm7.4` to `/usr/sbin/php-fpm8.5` - update custom images or mounted config files
* Docker: the image is based on **Ubuntu 26.04 LTS** (previously 20.04, end of standard support): R 4.6 (from 4.5), OpenSSL 3.5 (from 1.1.1), nginx 1.28, MariaDB client 11.8. Images built `FROM campsych/concerto-platform` must use the new package names (e.g. `libmariadb-dev`, `libaio1t64` for Oracle Instant Client) and keyrings with `signed-by` instead of `apt-key`, which no longer exists, and reinstall any R packages they compiled themselves
* upgraded to **Symfony 7.4** (LTS) and Twig 3
  * the `symfony/symfony` package is replaced by the individual components Concerto uses; custom code that needs other components (e.g. Form, Mailer, Serializer) must require them itself
  * user e-mail addresses are validated with the HTML5 pattern (previously a loose check): addresses with non-ASCII characters or without a dot in the domain are rejected when a user is saved
  * the session cookie gets the `Secure` flag when the panel is accessed over HTTPS, also behind a reverse proxy that sends `X-Forwarded-Proto`; **CONCERTO_COOKIES_SECURE**=true still sets it on every request
  * test base templates (view templates used as a test's base template) are rendered with Twig 3: the `{% spaceless %}` and `{% filter %}` tags and `{% for ... if ... %}` were removed - use `{% apply spaceless %}`, `{% apply ... %}` and `{% for ... %}{% if ... %}` instead. The starter content is not affected
  * two-factor authentication (Google Authenticator): a code from the previous or next 30 second period is accepted while its period is within 29 seconds of the current time (previously: always); the setting is `scheb_two_factor.google.leeway`
* **FOSOAuthServerBundle** replaced by **league/oauth2-server-bundle**:
  * existing API clients are migrated automatically by `concerto:setup`; their client id (`<id>_<randomId>`) and secret stay the same
  * previously issued access tokens are no longer valid - API consumers must request a new token
  * access tokens are now signed JWTs; the RSA key pair is generated by `concerto:setup` into **CONCERTO_OAUTH_KEY_DIR** (Docker: `/data/oauth`, otherwise `var/oauth`) - keep this directory persistent. The private key is created readable only by the user running `concerto:setup`; on non-Docker installations run it as the web server user, or make the key readable by that user (permissions 600/640/660), otherwise the token endpoint fails
  * the token endpoint `/oauth/v2/token` only accepts **POST** and only the **client_credentials** grant
  * the `/oauth/v2/auth` (authorize) endpoint was removed
  * the access token can still be passed as `access_token` query/form parameter, but the `Authorization: Bearer` header is preferred
* upgraded to **Doctrine ORM 3 / DBAL 4**
  * `doctrine:schema:update` only manages the tables mapped by Concerto's entities: data tables and other tables in the database are hidden from it by a schema filter (`Concerto\PanelBundle\Doctrine\UnmappedTablesSchemaFilter`). Do not remove this filter - without it Doctrine ORM 3 drops every table it does not map, including all data tables
  * the first `concerto:setup` after the upgrade removes Doctrine's `(DC2Type:...)` column comments from the OAuth tables; data is not changed
  * new tables keep the previous MySQL defaults (`utf8` / `utf8_unicode_ci`, InnoDB) through `doctrine.dbal.connections.local.default_table_options`
* data API (`/api/data/{table_id}`): insert/update field names must match the column names exactly as GET returns them (previously column names were only matched in lower case). A rejected request now returns a 400 response naming the unknown fields and listing the expected ones
* **MySQL 8** support (5.7, 8.0 and 8.4 are tested); `deploy/docker-compose/docker-compose.yml` now uses **MySQL 8.4** with **DB_VERSION**=8.4
  * MySQL 5.7 still works but is deprecated by Doctrine DBAL and will not be supported by DBAL 5
  * set **DB_VERSION** to the major.minor version of your MySQL server (e.g. `8.4`); the Docker image default stays `5.7`
  * existing installations: **back up `data/mysql` first and do not start `mysql:8.4` on a MySQL 5.7 data directory** - it fails (`Failed to initialize DD Storage Engine`), but its start attempts already write to the InnoDB files, after which 5.7 reports `log sequence number ... is in the future`. Either keep `image: mysql:5.7`, or move the data with a dump (with the old compose file still in place, run from `deploy/docker-compose`):
    ```
    docker compose exec database sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines --triggers concerto' > concerto.sql
    docker compose down
    sudo mv data/mysql data/mysql-5.7   # data/ is created by Docker and owned by root
    # switch to the new docker-compose.yml (mysql:8.4, DB_VERSION=8.4), then:
    docker compose up -d database   # wait until "ready for connections" in: docker compose logs database
    docker compose exec -T database sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" concerto' < concerto.sql
    docker compose up -d
    ```
    An in-place upgrade (start `mysql:8.0` once on the 5.7 directory, then `mysql:8.4`) also works, but accounts created on 5.7 use `mysql_native_password`, which MySQL 8.4 does not load: switch them while on 8.0 with `ALTER USER 'concerto'@'%' IDENTIFIED WITH caching_sha2_password BY '<password>';` (and the same for `root`)
  * the R test runtime supports MySQL 8's default `caching_sha2_password` authentication; with older MariaDB clients built on GnuTLS (e.g. custom images on Ubuntu 20.04) it reconnects over TLS, which MySQL 8 enables by default
  * data table and column names that became reserved words in MySQL 8 (e.g. `rank`, `groups`, `row`, `system`, `lead`) keep working in the panel, the data API and CSV import/export; your own SQL in tests (`concerto.table.query`) must quote such names with backticks, e.g. ``SELECT `rank` FROM scores``
* non-Docker installations: `env(...)` defaults in `app/config/parameters*.yml` must be strings - quote numeric and boolean values (see the `.dist` files)
* **CONCERTO_BEHIND_PROXY** is now parsed as a boolean; previously any non-empty value (including `false`) made SAML trust `X-Forwarded-*` headers. The Docker image default is `false`, so **SAML installations behind a TLS-terminating reverse proxy must set CONCERTO_BEHIND_PROXY=true**, otherwise SAML builds `http://` URLs and the login fails
